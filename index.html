JIRA-SVEL-204 Feature: Real-Time Property Match & Transaction State Engine
Merged to Production

User Story (INVEST Compliant)

As an active property buyer using the Svello mobile app,
I want to view intelligent property match cards and swipe or tap to record my interest,
So that I can initiate offer negotiations with the listing agent without repetitive search friction.

Technical Scope & Edge Cases

  • Pre-fetch next 5 property cards into memory for instant swipe responsiveness.
  • Handle currency display based on agent listing (SAR, USD, AED, INR).
  • Graceful degradation when offline: queue swipe actions in SQLite and sync on reconnect.
  • Trigger real-time push notification to listing agent via Firebase Cloud Messaging (FCM).

Gherkin Acceptance Criteria (Given / When / Then)

Scenario 1: Successful Match Acceptance
Given an authenticated buyer is viewing property match card "Aavkar Emerald"
When the buyer taps the green match checkmark or swipes right
Then the system emits a POST request to /api/v1/matches/respond with action: "ACCEPT"
And an offer record in state "Connected" is created in the Agent's CRM
And the UI smoothly slides the next property card without latency.

Scenario 2: Network Failure Resilience
Given the buyer loses cellular connectivity during a match swipe
When the swipe action completes
Then store the swipe payload in local cache with timestamp
And display subtle offline indicator "Saved. Will sync once online"
And auto-retry sync once connectivity returns without duplicate records.
